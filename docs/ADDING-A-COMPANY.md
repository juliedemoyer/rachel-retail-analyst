# Adding a New Company to Rachel

Runbook for onboarding a new watchlist company end-to-end.
**As of May 2026: company pages are typed TypeScript records in `final.ts`.** The legacy `app.html` flow described below in old revisions is gone — every page now reads from `lib/profiles/template/data/final.ts` via the `CompanyProfile` template.

Budget: **15-25 min editing per company once research is in hand.** Research is still the bottleneck (~45-90 min).

---

## THE THREE SOURCES — ALWAYS KEEP IN SYNC

Every company lives in **three places**. All three must be updated together whenever you add or edit a company. Missing any one leaves the system inconsistent.

| # | Source | What it controls |
|---|---|---|
| 1 | `data/companies/{slug}.md` | Profile data: financials, AI scores, notes. Canonical source. |
| 2 | `07_shared_sources.md § 3` (your notes vault) | Earnings calendar: `last_earnings`, `next_earnings`, `ir_url`. Cross-agent. |
| 3 | Redis via `tsx scripts/seed-profiles.ts --slug {slug}` | Live app: dashboard cards, leaderboard, benchmark, Ask Rachel. |

**And two supporting surfaces that must also be updated:**

| # | Source | What it controls |
|---|---|---|
| 4 | `app/(product)/app/companies/_section.ts` (find `<!-- {Company} -->`) | Companies grid card: financials displayed, use cases, vendor chips, updated date. |
| 5 | `app/components/Nav.tsx` (`COMPANIES` array) | Sidebar link. |

**Checklist for every new company or earnings update:**
- [ ] Edit `data/companies/{slug}.md` first (record of truth)
- [ ] Add/update row in `07_shared_sources.md § 3` (`last_earnings`, `next_earnings`, `ir_url`)
- [ ] Run `tsx scripts/seed-profiles.ts --slug {slug}` to push to Redis
- [ ] Update the HTML card in `_section.ts` (financials, use cases, "Updated" date)
- [ ] Run `node_modules/.bin/tsx --env-file=.env.local scripts/sync-calendar.ts` after any § 3 edit — this pushes to Redis AND regenerates `data/earnings-calendar.json`. Do NOT edit `earnings-calendar.json` directly.

**Never edit `_section.ts` without updating the MD file first. Never edit the MD file without syncing to Redis. Never add a company without a § 3 row. Never edit `data/earnings-calendar.json` directly — it is auto-generated.**

## Page-quality rules (apply to every company page)

These are non-negotiable. A page that fails any of them is incomplete.

1. **Baseline is the latest FY, not a date.** `cadence.baseline.label` must be `FY2025` (or whatever the company's most recent published full year is). The date in `cadence.baseline.date` is the publication date, not the period.
2. **OP growth vs prior FY is mandatory.** `investor.headline.opMargin.growth` must include `absolute`, `pct`, and `basis` (e.g. `"OP €2,056M FY2025 vs €1,337M FY2024"`). Mark `estimated: true` if calculated from quarterlies. The renderer colours the chip green for positive growth, rust for negative.
3. **`cadence.next` must reflect reality.** If the next milestone is already published (e.g. Q1 2026 reported 29 Apr 2026), promote it to `lastReported` and set `next` to the next forward-looking event. The auto-demoter in `index.ts` only handles past dates that parse as ISO strings; explicit known events should be set by hand. Use the `"Late April 2026 — verify on IR"` pattern when uncertain.
4. **Sources: minimum 5 clickable links per company.** Each must point at a real article, IR doc, or vendor case study. **Banned source labels:** `"from vendor footprint"`, `"Google search"`, or any link that goes to a homepage instead of the actual content. The IR source link must hit the investor relations subpage, not the company homepage. The runtime filter `stripUnsourcedStackRows` in [index.ts](2. Pipeline & Dashboard/rachel-retail-companion/lib/profiles/template/data/index.ts) drops any `production.stackTable` row whose source label matches `/from vendor footprint/i` or has no URL.
5. **`leadership.presenter` is mandatory.** Every company has a CIO / CTO / CDIO / CDO / Chief Strategy & Tech / VP-of-ML who fronts the AI agenda. Find theirs and cite the source. Reference: AB InBev → David Almeida (CSTO); ASOS → Victoria Arden + Papinder Dosanjh; Adidas → Fumbi Chima (CIO); Burberry → Charlotte Baldwin (CIO).
6. **Per-tool sources on `production.namedTools`.** Each tool listed must include `source: { label, url }` — vendor case study (Microsoft customer stories, Google Cloud customers, AWS customer stories), trade press (ConsumerGoods.com, Klover.AI, Manufacturing Leadership Council), or an earnings transcript line. No tool gets listed without a source.
7. **Peer comparison must be same vertical.** Adidas → Nike, Puma, Under Armour. Not Adidas → H&M. Same-subsector peers are auto-generated by `batch6_peers.ts` from [peer-map.ts](2. Pipeline & Dashboard/rachel-retail-companion/lib/profiles/template/data/peer-map.ts). If the new company is in an existing subsector, just add the slug to `peer-map.ts`. If it's in a new subsector, add the subsector and external reference peers.
8. **Featured hyperscaler case studies in 2D Vendor Stack.** When the company has a public Microsoft / Google / Anthropic / OpenAI / Mistral / NVIDIA / AWS customer story, the partner entry in `vendorStack.namedPartners` must use the rich shape with `caseStudy: { label, url }` and a 1-line `note`. The renderer surfaces these as a click-through card above the chip list.
9. **`brands.value` is a count; `brands.note` is the names.** Format: `brands: { value: "8", note: "Aperol, Campari, Wild Turkey, ..." }` or `brands: { value: "200+", note: "Johnnie Walker, Smirnoff, ..." }`. The metric cell shows the count as the headline; the names appear as the subtitle.
10. **AI search sweep before writing.** For every company, run these searches and harvest sources before drafting use cases:
    - `{Company} FY{latest} results revenue operating profit`
    - `{Company} AI artificial intelligence Microsoft Google` (and Anthropic / OpenAI / Mistral / NVIDIA / AWS variants)
    - `{Company} CIO CTO Chief Digital AI leader executive`
    - `{Company} {flagship-brand} AI campaign generative` (per major brand for byMaison highlights)
11. **Every promoted `lastReported` needs a matching `investor.quarterlyUpdate`.** The cadence chip just labels WHEN the milestone happened; the actual quarter's numbers (revenue / OP / regional splits / reading note / source) live in `investor.quarterlyUpdate.metrics`. If you promote Q1 / H1 / Q3 to `lastReported` without populating `quarterlyUpdate`, the page silently renders the cadence chip but no quarterly banner — exactly the Carrefour Q1 bug. Required fields: `label`, `date`, `blurb`, `metrics: [{label, value, trend}]`, `reading`, `source: { label, url }`.

## Typical AI sources catalogue (built from the watchlist rebuilds)

When researching a new company, scan these recurring publishers and customer-story collections first. They cover ≥80% of named-tool sources across the watchlist.

**Hyperscaler / vendor customer stories** (highest authority):
- Microsoft Customer Stories: `microsoft.com/en/customers/story/...` — Adidas, Albert Heijn, Arla, ASOS, Campari, Carlsberg, Danone, Estée Lauder, Heineken, Reckitt, M&S all have stories here.
- Google Cloud Customers: `cloud.google.com/customers/...` — AB InBev (Pluto7), Ferrero (BigQuery), Argos, Unilever (Vertex AI).
- AWS Customer Stories: `aws.amazon.com/solutions/case-studies/...` — Heineken, Diageo (Project Halo via Bedrock + Titan).
- Microsoft Ads case studies: `about.ads.microsoft.com/en/resources/discover/case-studies/...` — M&S.
- NVIDIA blog + customer stories: `blogs.nvidia.com/blog/...` — L'Oréal, Unilever, Nestlé.
- Snapchat Newsroom: `newsroom.snap.com/...` — Gucci's Sponsored AI Lens.
- Salesforce / Adobe / Databricks / Snowflake / Snowplow customer-story pages — Haleon (Salesforce Agentforce), Estée Lauder (Adobe Firefly), Burberry/Barilla/HelloFresh (Databricks/Snowflake/Snowplow).
- SI build partners with case studies: Accenture, EPAM, BCG, McKinsey QuantumBlack, IBM, Bynder, PALO IT, TCS, SymphonyAI.

**Trade press AI scans:**
- ConsumerGoods.com, Klover.AI, Manufacturing Leadership Council, Tiger Advisory, AI Expert Network, DigitalDefynd.
- Sector-specific: Marketing Dive, Retail Dive, Food Dive, Beverage Daily, Spirits Business, Drinks Business, Cosmetics Business, Premium Beauty News, Drapers, Retail Gazette, Just-Style, Modaes, FashionNetwork, Glossy.
- UK case studies: TechInformed, CIO Dive, CDO Magazine, Retail Insight Network.
- Tech publications: The New Stack, AI Business, AI Magazine, AI Data Analytics Network, Technology Magazine.

**Investor sources** (always required):
- Company IR press release for the latest results — never the IR homepage. Use the deep link to the specific FY/quarter announcement.
- Annual report PDF if available.
- Earnings call transcript via Investing.com, Yahoo Finance, or the company's own transcript page.

**Leadership sources:**
- Company "Our Leaders" / "Management" page (deep link to the named exec, not the team index).
- LinkedIn profile (only if no first-party page).
- Press release announcing the appointment (CIO Dive, Fashion Network, RetailDive, ESM, etc.).

## Step 1: Research (45-90 min)

Gather before touching any file:

- Latest annual report PDF + most recent quarterly/half-year disclosure.
- FY revenue, op margin, **op profit growth vs prior FY** (absolute + %), employees, gross margin if material.
- Stock ticker + exchange + reporting cadence (quarterly / semi-annual / annual).
- Confirmed AI/tech vendor relationships with public customer-story URL where possible.
- 3-5 named AI tools or use cases in production, each with a concrete source URL.
- A sentence per major brand for `byMaison.maisons` (only when the brand has its own AI artefact).
- Named CIO / CTO / CDIO / CDO and a source for that name (job announcement, customer-story quote, or "Our Leaders" page).

Tag each piece of evidence with the source URL so you can paste it straight into the record.

## Step 2: Vault company file (~10 min)

Create `/path/to/vault/06_rachel domain brain/companies/{slug}.md` with:

```markdown
---
company: {Display Name}
country: {Country}
sector: {Subsector}
ticker: {TICKER}
---

## Overview
One paragraph: scale, geography, business model.

## AI narrative
What they say publicly. Quadrant: {silent_builder | narrative_led | performer | not_visible | native}. Composite score: X.X / 5.

## AI in production
- {Tool 1}: [{source label}]({url})
- {Tool 2}: ...

## Vendor relationships
- Microsoft: {Confirmed / Signalled / None} — {evidence}
- Google Cloud: {Confirmed / Signalled / None}
- AWS / Anthropic / OpenAI / Mistral / NVIDIA: as applicable

## Financials (FY____)
- Revenue: €Xb (+X% reported / +X% organic)
- OP / OP margin: €Xb / X% (vs {prior FY})
- Employees: Xk

## Earnings calendar
- Last reported: {date, period}
- Next earnings: {date, period}

## Key quotes
> "..." — {Speaker, earnings call, date}

## Rachel notes
Open loops, stale flags, and signals for any sibling agents you run.
```

## Step 2b: Generate the `data/companies/{slug}.md` stub (~1 min)

Before building the full `final.ts` record, create the lightweight MD profile used by the Matrix, Companies filter, Leaderboard, and Benchmark pages:

```bash
node scripts/generate-company-stubs.mjs
```

This parses `app/(product)/app/companies/_section.ts` and generates stub files in `data/companies/` for any company that does not already have one. Then seed to Redis:

```bash
tsx scripts/seed-profiles.ts --slug {slug}
```

The stub script can be rerun any time new companies are added to `_section.ts` — it skips existing files.

## Step 3: Add the TypeScript record to `final.ts` (~15 min)

This is the meat. Append a new `export const {slug}_final: Partial<CompanyTemplateData>` to [final.ts](2. Pipeline & Dashboard/rachel-retail-companion/lib/profiles/template/data/final.ts) following the template below, then add the slug to the `final` export at the bottom.

### Template

```typescript
export const {slug}_final: Partial<CompanyTemplateData> = {
  cadence: {
    baseline: { label: "FY2025", date: "YYYY-MM-DD" },
    lastReported: { label: "Q1 2026 results", date: "YYYY-MM-DD" },
    next: { label: "H1 2026 results", date: "Late July 2026" },
    blurb: "FY2025 published {date}. Q1 2026 results {published date or 'late April; verify on IR'}.",
  },
  investor: {
    fiscalYearLabel: "FY2025 baseline",
    headline: {
      revenue: { value: "€Xb", reported: "+X%", organic: "+X% LFL", note: "FY2025" },
      opMargin: {
        value: "X.X%",
        growth: { absolute: "+€XM", pct: "+X%", basis: "OP €Xb FY2025 vs €Xb FY2024" },
        note: "{any extra colour}",
      },
      employees: { value: "XK" },
    },
    operatingComplexity: {
      hq: { value: "{Country} 🇽🇽" },
      countries: { value: "X+" },
      brands: { value: "X+", note: "Brand 1, Brand 2, ..." },
      stores: { value: "X+" }, // omit if not retail
    },
    whyMatters: "1-2 sentence framing: business shape + where AI lands hardest.",
  },
  aiPerception: {
    quadrant: "silent" | "narrative_led" | "performer" | "not_visible" | "native",
    label: "Silent Builder · 3.0",
    rhetoric: 1-5,
    production: 0-5,
    evidence: "confirmed" | "estimated",
    rubric: "v1",
    lastScored: "YYYY-MM-DD",
  },
  narrative: {
    framing: { headline: "...", body: "..." },
    dedicatedSection: { headline: "...", body: "..." }, // optional
  },
  leadership: {
    presenter: {
      html: "<strong>{Name}</strong> · {Title}. {1 sentence on background or Microsoft/Google customer-story quote}.",
      source: { label: "...", url: "..." },
    },
    appointmentsNote: "Optional: distinct seat / fused role observation.",
  },
  production: {
    namedTools: {
      tools: [
        {
          html: "<strong>{Tool}</strong> <span style=\"font-size:10px;color:var(--text-dim);font-weight:400\">· {vendor}</span> — {1 line description with metric if available}.",
          source: { label: "...", url: "..." },
        },
        // ... 3-5 tools total
      ],
    },
    quantifiedROI: { // optional but encouraged
      html: "<strong>{Metric 1}:</strong> X. <strong>{Metric 2}:</strong> Y.",
      source: { label: "...", url: "..." },
    },
    consumerFacing: "<strong>Yes / Indirect / No.</strong> {1 line}",
    genAI: { mentioned: true|false, vendors: [{ name: "...", url: "..." }], note: "..." },
    stackTable: [
      { layer: "...", product: "...", use: "...", source: { label: "...", url: "..." } },
      // The runtime filter drops any row without a clickable URL or labelled "from vendor footprint".
    ],
  },
  vendorStack: {
    namedPartners: [
      // FEATURED partners (with case study) get the rich rendering — card with click-through + note.
      {
        name: "Microsoft — {what it powers}",
        status: "confirmed",
        caseStudy: { label: "Microsoft Customer Story — {Company} {topic}", url: "https://www.microsoft.com/en/customers/story/..." },
        note: "1-line summary of the case study with a metric.",
      },
      // Plain partners (no case study yet) get the chip rendering.
      { name: "Other partner", status: "confirmed" },
      // Always close out the absent hyperscalers explicitly so vendor-gap analysis is clean.
      { name: "Anthropic", status: "absent" },
      { name: "OpenAI (direct)", status: "absent" },
      { name: "Mistral", status: "absent" },
      { name: "AWS", status: "absent" },
    ],
    partnersNote: "1-line summary of the vendor posture.",
  },
  byMaison: { // optional — only if the company has multiple distinct brands with their own AI footprint
    maisons: [
      { brand: "...", description: "...", source: { label: "...", url: "..." } }, // source optional
    ],
    note: "1-line on how brand-level AI relates to Group-level.",
  },
  rachelNotes: [
    { lead: "Quick take.", body: "Financials in 1-2 sentences." },
    { lead: "AI posture.", body: "Quadrant, marquee artefacts, leadership tell." },
    { lead: "Vendor footprint.", body: "Which vendors are disclosed, and which are absent from the public record." },
    { lead: "Open loop.", body: "Optional: what to watch / verify next." },
  ],
  sources: [
    // 5+ entries minimum. Mix: IR press release, annual report PDF, 1-2 financial-press articles,
    // 1-2 vendor case studies, leadership announcement, IR hub page.
    { label: "...", url: "..." },
  ],
  furtherReading: [ // optional
    { label: "...", url: "..." },
  ],
  askPrompts: [
    "What did {Company} report for FY2025?",
    "How does {Company} use {flagship AI tool}?",
    "Who runs AI at {Company}?",
    // ... 3-5 prompts
  ],
};
```

### Wire it up

1. Append the record to `final.ts` (above the `export const final = {...}` block at the bottom).
2. Add `"slug": slug_final,` to the export map. **Order matters:** all const declarations must come before they're referenced in the export, so put the export at the bottom.
3. Add the slug to [peer-map.ts](2. Pipeline & Dashboard/rachel-retail-companion/lib/profiles/template/data/peer-map.ts) under the right subsector. If the subsector is new, add it to the `Subsector` union, `SUBSECTOR_LABEL`, and `EXTERNAL_PEERS` maps.
4. Add a `NAME` entry to [batch6_peers.ts](2. Pipeline & Dashboard/rachel-retail-companion/lib/profiles/template/data/batch6_peers.ts) for the same-vertical peer name lookup.

## Step 4: Sidebar entry (~2 min)

Add a `LinkSpec` entry to the `COMPANIES` array in [Nav.tsx](2. Pipeline & Dashboard/rachel-retail-companion/app/components/Nav.tsx). Keep alphabetical order. The arrow prefix and ★ for prioritised companies are added by the renderer — labels should be plain.

```typescript
{ href: "/app/companies/{slug}", label: "{Display Name}" },
```

The ★ is now driven by the runtime watchlist (toggled via the "Add to My Priority Watchlist" button on the profile page). Don't put a ★ in the label.

## Step 5: Upstash Redis (`rachel:accounts`) (~3 min)

Add one object to the JSON array in the `rachel:accounts` key:

```json
{
  "id": <next integer>,
  "company": "Display Name",
  "country": "Country",
  "sector": "Subsector",
  "ticker": "TICKER",
  "aiMaturity": 3,
  "quadrant": "challenger",
  "nextEarnings": "YYYY-MM-DD",
  "approvedAt": "YYYY-MM-DDTHH:mm:ss.000Z",
  "notes": "1 sentence framing",
  "vendors": { "microsoft": "confirmed", "google": "none", "aws": "none" },
  "financials": { "revenue": "€Xb", "grossMargin": "X%", "opMargin": "X%", "employees": "Xk", "reportingPeriod": "FY2025" },
  "pendingIngestion": false
}
```

Options: ask Rachel to add it via chat, `PUT /api/accounts`, or edit Upstash directly.

## Step 6: Ingest IR documents (~10 min)

Upload PDFs (annual report, earnings transcripts, investor deck) via the ingestion endpoint so Ask Rachel can answer questions grounded in this company's filings.

Per document:
- `accountId`: the slug
- `source`: `ir_filing`
- `title`: e.g. `{Company} FY2025 Annual Report`
- `publishedAt`: ISO date

Verify by going to Ask Rachel, selecting the company, and asking "What did {Company} say about AI in their last earnings call?" — should return a grounded answer with passage citations.

## Step 7: Verify end-to-end (~5 min)

- [ ] `/app/companies` index card renders (search "{Company}" → card visible with right sector/quadrant).
- [ ] `/app/companies/{slug}` profile renders without empty / placeholder sections.
- [ ] Investor snapshot: brand count + names display correctly (count in big number, names in subtitle).
- [ ] Operating margin shows OP growth in green/rust.
- [ ] Sources card shows ≥5 clickable links.
- [ ] Vendor stack: featured partners render as cards with case-study click-throughs; others as chips.
- [ ] "Add to My Priority Watchlist" button toggles the ★ in the sidebar and adds the company to `/app/priority`.
- [ ] Sidebar entry appears under the indented Companies sublist.
- [ ] Ask Rachel: grounded answer for a company-specific IR question.
- [ ] Redis: `rachel:accounts` entry has `pendingIngestion: false`.
- [ ] Vault: `06_rachel domain brain/companies/{slug}.md` exists.
